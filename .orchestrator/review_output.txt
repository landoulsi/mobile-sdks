### Key Findings & Recommendations

#### 1. Security & Sensitive Data Handling (PCI-DSS Consideration)
- **Plaintext Card Data in Default `toString()`**: In [`PaymentMethod.Card`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/PaymentMethod.kt#L34-L42), the class is defined as a Kotlin `data class` without overriding `toString()`. As a result, any standard logging, debugging, or crash reporting that prints instances of [`PaymentMethod.Card`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/PaymentMethod.kt#L34-L42) will dump plaintext PANs (`number`) and CVVs (`cvc`). It is strongly recommended to override `toString()` to mask the PAN (preserving only the last 4 digits) and redact the CVC (e.g., `"***"`).
- **Token & Payload Exposure**: In [`PaymentResult.Success`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/PaymentResult.kt#L47-L57), the `token` and `rawPaymentData` properties contain sensitive wallet tokens and cryptographic payloads. A custom `toString()` or debug formatter can help avoid unintended disclosure in log pipelines.

#### 2. Domain Modeling & Defensive Validation
- **Floating-Point Input Validation in [`Money.fromMajorUnits`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/Money.kt#L75-L79)**: The helper accepts a `Double` and converts it via `roundToLong()`. It should defensively validate that `amount.isFinite()` (not `NaN` or `Infinite`) before rounding to prevent unexpected `Long` sentinel conversions.
- **Negative or Invalid Currency Decimal Places in [`Currency`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/Currency.kt#L10-L14)**: The [`Currency`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/Currency.kt#L10-L14) model accepts arbitrary `decimalPlaces: Int`. Adding an `init` requirement such as `require(decimalPlaces >= 0)` and `require(code.isNotBlank())` will guard against malformed currency objects.
- **Currency Symbol Placement in [`Money.formattedWithSymbol`](file:///Users/ahmed/Work/payment-sdk/mobile/shared/src/commonMain/kotlin/com/landoulsi/payment/shared/model/Money.kt#L39-L46)**: The current implementation always prefixes the symbol (e.g., `"$10.00"`). For currencies where the symbol or code is customarily placed as a suffix (or formatted with a space), consider future support for localized currency formatting.
